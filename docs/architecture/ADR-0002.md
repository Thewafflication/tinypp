# ADR-0002: Audited component reuse

**Content type:** Architecture decision record

**Status:** Proposed

**Date:** 2026-10-31

## Context

TinyCC contains LGPL text and DMC has a qualified Boost grant plus third-party
assets. The original dmc distribution inventory identified runtime/library
source. The separately added Compiler repository now supplies C/C++ compiler
source; ADR-0010 evaluates its suitability before adaptation.

## Decision Drivers

C++98 hosted completeness; audited TinyCC/DMC reuse; bounded initial target;
reproducible WSP evidence.

## Considered Options

1. Audit and selectively reuse source.
2. Assume one license covers both distributions.
3. Use dmc.exe as the new front end.

## Decision

Inventory every candidate file before import. Reuse TinyCC infrastructure and
audited DMC runtime/library and compiler portions where feasible, subject to
ADR-0010 extraction/build gates. Use DMC behavior for
comparison, never as the standards oracle. Implement a project-owned C++ front
end if suitable front-end source is unavailable. Separate compiler and user-
program runtime obligations; decide distribution licensing after the
inventory.

## Rationale

Available binaries do not establish reusable compiler source. Selective reuse
exposes technical and license constraints.

## Consequences

### Positive

Reproducible provenance and an explicit fallback.

### Negative

Audit and replacement work can exceed initial expectations.

### Follow-up

REQ-0035; REQ-0036. M0 inventories source availability and per-file
obligations; M1 demonstrates reuse feasibility.
