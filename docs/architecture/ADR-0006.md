# ADR-0006: Standards-led verification

**Content type:** Architecture decision record

**Status:** Proposed

**Date:** 2026-10-31

## Context

Reference compilers have documented C++98 gaps. Agreement can reproduce an
implementation bug. WSP requires controlled cases and retained evidence.

## Decision Drivers

C++98 hosted completeness; audited TinyCC/DMC reuse; bounded initial target;
reproducible WSP evidence.

## Considered Options

1. Clause-based oracles with differential corroboration.
2. Compiler majority as truth.
3. Only positive smoke tests.

## Decision

Use final-edition anchors and the adopted defect ledger as oracles. Expand
controlled cases into fixture variants. Cover positive, diagnosable-negative,
link, execution, ABI and library complexity behavior. Corroborate supported
subsets with pinned GCC/Clang strict modes and DMC where available. Classify
undefined, unspecified, implementation-defined and no-diagnostic-required
behavior before comparison. Verify external export integration against its standards oracle when
references lack it. Component-level template/library evidence belongs to the
external project; retain local interface acceptance results.

## Rationale

Avoids false conformance from consensus or undefined behavior. Finite testing
supports a coverage claim rather than proving all programs.

## Consequences

### Positive

Reviewable and traceable evidence.

### Negative

Oracle review requires specialist effort.

### Follow-up

REQ-0038 through REQ-0041; testing/STRATEGY.md. M1 builds CI/evidence support;
later milestones extend clause coverage.
