# ADR-0007: Exact WSP adoption and staged completion

**Content type:** Architecture decision record

**Status:** Proposed

**Date:** 2026-10-31

## Context

Existing staged submodule additions must be preserved. WSP is four commits
after 1.4.0. Copied templates do not establish process compliance.

## Decision Drivers

C++98 hosted completeness; audited TinyCC/DMC reuse; bounded initial target;
reproducible WSP evidence.

## Considered Options

1. Adopt existing immutable commit with individual dispositions.
2. Silently reset to a release tag.
3. Claim compliance from templates.

## Decision

Use the existing WSP gitlink unchanged. Record the exact commit, selected
profiles and individual requirement dispositions. Keep the planning package
Proposed until normal review accepts it. Distinguish milestone allocation from
approved release deferrals. Build artifact lint, CI, security, documentation
and release evidence before claiming satisfaction.

## Rationale

Preserves user state and prevents inaccurate process claims.

## Consequences

### Positive

Reproducible process baseline.

### Negative

Tooling and approval records remain future work.

### Follow-up

REQ-0038 through REQ-0043; process/wsp-adoption.md; ROADMAP.md.
