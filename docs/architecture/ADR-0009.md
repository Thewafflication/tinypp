# ADR-0009: Qualified types and full-expression lifetimes

**Content type:** Architecture decision record

**Status:** Proposed

**Date:** 2026-10-31

## Context

The scalar prototype has distinct primitive ranks, readonly values and
non-const references. Its ScalarType plus declaration flags are a feasibility
representation. Pointers, arrays, function types, class/member types, full cv
qualification and temporary lifetimes need a richer representation before
M3/M4 completion. Const-reference temporaries are intentionally rejected;
scoped generated-C expression temporaries alone cannot establish their full
C++98 lifetime, especially across calls and comma expressions.

The existing external templates/library project needs a deliberate compiler
interface. Its repository and interface version remain unidentified here;
this ADR does not invent or freeze that project's schema.

## Decision Drivers

- Correct C++98 type equivalence, conversions and overload resolution.
- Separate type identity, value category, object identity and storage layout.
- Explicit temporary construction/destruction and exception cleanup regions.
- A versioned integration boundary with the externally owned template work.
- Preserve the working scalar regressions during incremental migration.

## Considered Options

1. Canonical qualified type records and explicit lifetime regions.
2. Continue adding independent booleans to scalar expression/declaration nodes.
3. Infer C++ type/category/lifetime behavior from generated C expressions.

## Decision

Introduce a compiler-owned canonical type context before pointer, class and
const-reference temporary support is accepted. Represent primitive, pointer,
reference, array, function, record, enumeration and member-pointer forms with
explicit qualification at each applicable type level. Keep record identity
stable while its definition changes from incomplete to complete. Allocate
layout and calling conventions to the target ABI layer.

Retain an explicit C++98 lvalue/rvalue distinction independent of constness.
The current shared is_lvalue query remains the prototype contract until
expression nodes carry the complete type/category model. Qualification changes
need reviewed conversion sequences and reference-binding rules rather than
dropping flags or relying on target C implicit conversions.

Represent full expressions and lexical cleanup scopes explicitly. Bind
materialized temporaries to their required lifetime region; track actual
construction order and reverse cleanup, including exceptional exits. Extend
const-reference binding only after this region model and its tests exist.
Generated-C expression blocks remain limited scalar implementation machinery.

Keep type IDs local to a compilation context. Before exchanging types or
instantiation requests with the other project, define a reviewed, versioned
structural interchange contract with ownership, source identity, diagnostic,
symbol and ABI fields. Do not export raw host pointers as stable identities.
Capture any new observable interface obligations as requirements before
accepting that contract.

## Rationale

Scalar flags already expose the difference between immutable objects and
value categories. More flags would obscure nested pointer qualification and
temporary ownership. C lowering cannot be the source of truth for C++
references, class layout or exception cleanup. Canonical types make these
relations inspectable while leaving the target representation replaceable.

## Consequences

### Positive

The next semantic layer has a defined migration boundary and verification
target. External template integration can consume deliberate type identities.

### Negative

The migration adds type-context and lifetime infrastructure before several
visible language features. The current bool int-carrier ABI remains a spike;
final bool/object layout requires explicit ABI review and compatibility work.

### Follow-up

M3 type work covers type equivalence, promotions/conversions, cv qualification
at each indirection, reference viability/ranking and incomplete types. M4
adds object layout, construction and all normal/exceptional cleanup exits.
Preserve scalar, namespace, source-phase and multi-unit regression behavior.

Build matrices from the final edition plus the adopted defect ledger before
acceptance. Historical conditional cv behavior can differ across drafts and
later resolutions; the prototype's mixed-const conditional boundary remains
explicit until reconciliation. Coordinate the external schema before M5.
