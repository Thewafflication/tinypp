# REQ-0006 — Required diagnostics

**Content type:** Requirement

**Status:** Proposed

**Source:** S2 [intro.compliance]; see [source register](../research/standards.md).

## Scope

Tiny++ hosted C++98 implementation and its controlled engineering records.
Allocation: M3. Target scope follows ADR-0003; intermediate subsets do not
establish full conformance.

## Requirement

The compiler shall emit at least one diagnostic for a translation unit
containing a violation of a diagnosable C++98 syntax or semantic rule.

## Rationale

Makes required diagnostics an explicit, reviewable part of the C++98 product
baseline instead of inheriting an unverified upstream assumption.

## Verification

**Method:** Test and review

**References:** [TC-0006](../testing/cases/TC-0006.tex).

Use separate files with an undeclared identifier, inaccessible private member,
ambiguous overload and malformed declarator; each emits a diagnostic. Do not
require diagnostics for no-diagnostic-required ODR cases.

## Relationships

- **Derived from:** Source above and stakeholder C++98 compiler objective.
- **Depends on:** [REQ-0001](REQ-0001.md); detailed standards allocation in REQ-0002.
- **Conflicts with:** No known conflict; deviations require impact review.

## Tailoring

None for a full conformance claim. Intermediate milestones may implement a
published subset without claiming that this requirement is verified.

## Implementation Record

Partial semantic diagnostics include checked LF/CRLF identifier locations;
see [compiler foundation](../process/compiler-foundation.md). The full
diagnosable-rule inventory and verification remain open.
