# REQ-0007 — Strict failure policy

**Content type:** Requirement

**Status:** Proposed

**Source:** Project policy beyond ISO minimum; see [source register](../research/standards.md).

## Scope

Tiny++ hosted C++98 implementation and its controlled engineering records.
Allocation: M3. Target scope follows ADR-0003; intermediate subsets do not
establish full conformance.

## Requirement

The driver shall return a nonzero status when strict-mode diagnostics identify
an ill-formed translation unit.

## Rationale

Makes strict failure policy an explicit, reviewable part of the C++98 product
baseline instead of inheriting an unverified upstream assumption.

## Verification

**Method:** Test and review

**References:** [TC-0007](../testing/cases/TC-0007.tex).

Invoke the strict driver on the diagnosed inputs specified by the required-diagnostics case; assert nonzero
exit and no newly published object or executable, distinguishing compiler
rejection from missing infrastructure.

## Relationships

- **Derived from:** Source above and stakeholder C++98 compiler objective.
- **Depends on:** [REQ-0001](REQ-0001.md); detailed standards allocation in REQ-0002.
- **Conflicts with:** No known conflict; deviations require impact review.

## Tailoring

None for a full conformance claim. Intermediate milestones may implement a
published subset without claiming that this requirement is verified.

## Implementation Record

Partial scalar implementation and fixture evidence are recorded in the
[compiler foundation](../process/compiler-foundation.md). The complete
requirement and its parent TC remain open; no full verification is claimed.
