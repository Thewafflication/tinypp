# REQ-0035 — Dependency provenance

**Content type:** Requirement

**Status:** Proposed

**Source:** Local tinycc/COPYING; dmc/LICENSE; see [source register](../research/standards.md).

## Scope

Tiny++ hosted C++98 implementation and its controlled engineering records.
Allocation: M0. Target scope follows ADR-0003; intermediate subsets do not
establish full conformance.

## Requirement

The project shall record source origin, revision, per-file license and
permitted reuse scope for each reused dependency component.

## Rationale

Makes dependency provenance an explicit, reviewable part of the C++98 product
baseline instead of inheriting an unverified upstream assumption.

## Verification

**Method:** Inspection and analysis

**References:** [TC-0035](../testing/cases/TC-0035.tex).

Inspect all proposed import paths including bundled third-party library files
against their own notices; verify compiler code versus runtime code boundaries
and identify missing source as unavailable, never inferred from binary
presence.

## Relationships

- **Derived from:** Source above and stakeholder C++98 compiler objective.
- **Depends on:** [REQ-0001](REQ-0001.md); detailed standards allocation in REQ-0002.
- **Conflicts with:** No known conflict; deviations require impact review.

## Tailoring

None for a full conformance claim. Intermediate milestones may implement a
published subset without claiming that this requirement is verified.

## Implementation Record

A partial [file-level inventory](../research/reuse-audit.csv) records pinned
identities, observed notices and unresolved actions for selected backend and
runtime candidates. Transitive sources and distribution obligations remain
open; this record does not close the requirement or its parent TC.
