# REQ-0044 — Dependency integration boundary

**Content type:** Requirement

**Status:** Proposed

**Source:** Project; ADR-0004; see [source register](../research/standards.md).

## Scope

Tiny++ hosted C++98 implementation and its controlled engineering records.
Allocation: M1. Target scope follows ADR-0003; intermediate subsets do not
establish full conformance.

## Requirement

The compiler architecture shall separate C++ semantic analysis from target
emission through a documented typed lowering interface.

## Rationale

Makes dependency integration boundary an explicit, reviewable part of the
C++98 product baseline instead of inheriting an unverified upstream
assumption.

## Verification

**Method:** Inspection and analysis

**References:** [TC-0044](../testing/cases/TC-0044.tex).

Review interface contracts for types, ownership, control flow, object layout
and EH; demonstrate scalar lowering followed by cleanup/virtual-call probes,
with deterministic rejection of unsupported operations rather than silent C
semantics.

## Relationships

- **Derived from:** Source above and stakeholder C++98 compiler objective.
- **Depends on:** [REQ-0001](REQ-0001.md); detailed standards allocation in REQ-0002.
- **Conflicts with:** No known conflict; deviations require impact review.

## Tailoring

None for a full conformance claim. Intermediate milestones may implement a
published subset without claiming that this requirement is verified.

## Implementation Record

Partial scalar implementation and fixture evidence are recorded in the
[compiler foundation](../process/compiler-foundation.md). The complete
requirement and its parent TC remain open; no full verification is claimed.
